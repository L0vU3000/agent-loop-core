# Memory and evidence

Run evidence is transient and detailed. Machine-facing memory is durable and concise. Curated
vault notes preserve the broader reasoning humans need.

When Eval finds a failure worth teaching, record its symptom, cause, fix, and prevention in
[[memory/errors]]. Record load-bearing choices in [[memory/decisions]] and machinery changes in
[[memory/changelog]]. These entries are direct inputs to `pipeline-improve`, so keep them factual
and actionable.

Use a vault decision, research note, recommendation, or incident when the context would make
memory noisy. A memory entry may link to that note. Consuming-project details remain under
[[vault/project/README|vault/project/]] and are not reusable core content by default.
